# Exact order statistics of min-plus profiles with sparse strict turns

Let A and B have dimensions p×d and d×q, with exact real entries and d≥1. The profile at (i,j) has values A[i,k]+B[k,j] indexed by k. Given one rank per cell, the score and its original index in lexicographic (score,index) order can be found for all cells in soft-O(d(p+q)+pq+H) arithmetic and comparison time, where H is the total count of strict interior local-minimum plateaux across profiles. All repeated scores count separately. This is a sparsity-sensitive bound, not an improvement for unrestricted min-plus multiplication.

## Static reporting of extrema

Use middle indices 0 through d−1. For t from 0 through d−2, define R_i(t)=A[i,t+1]−A[i,t] and C_j(t)=B[t,j]−B[t+1,j]. The profile derivative is R_i(t)−C_j(t). A strict interior local-minimum plateau starts at k exactly when R_i(k−1)<C_j(k−1) and the suffix R_i[k:] is lexicographically greater than C_j[k:]. The first condition gives a strict descent into the plateau; the second says the first later nonzero derivative is positive and exists.

Assign equality-aware lexicographic ranks to all p+q suffixes, backwards by layer: sort (current digit,next rank) and assign equal tuples equal rank. At layer k, sweep the column IDs in increasing C_j(k−1), inserting row IDs with R_i(k−1)<C_j(k−1) into an ordered set keyed by (suffix rank,row ID). Report every active row whose suffix rank strictly exceeds the querying column's suffix rank. Ties are handled by strict inequalities on both coordinates. Each layer costs soft-O(p+q) plus the output count. Group outputs by cell in increasing k. Negating both matrices gives the corresponding maxima; the number of maxima is at most the number of minima plus one per cell, because signs alternate at successive turns after ignoring zero derivatives. For d=1 return the sole index directly.

## Disjoint sorted arms

Partition each profile at the starts of its reported valley plateaux, putting each cut vertex into the block on its right. Ignoring zero derivatives, a block has no negative-to-positive transition, so its scores weakly rise and then weakly fall. Pick the start of its interior maximum plateau if present; otherwise the block is monotone and an apex can be obtained by comparing endpoints. Align the two ordered extrema lists in linear time. Put the apex in the ascending prefix and reverse the disjoint remaining suffix. The resulting sorted arms cover every index exactly once and support constant-time score access from the original factors.

For a restricted query with a dynamic backend, only assume maintained range enumeration of the valley starts, random-access scores, and a first-nonzero derivative query on any specified interval. Start the same blocks at the query's left endpoint and its interior valley starts. A valley clipped at the right endpoint may be kept as an extra cut. Within a block, the first-nonzero suffix derivative is positive exactly at derivative positions at or before its last positive derivative. Binary search for that position gives the apex one index later; use the first vertex if no positive derivative exists. Restrict each suffix test to the current block. For a query with H_I reported valleys this takes soft-O(H_I+1) oracle calls and arithmetic operations, plus the cost to enumerate the valleys. The bound does not assert a new update algorithm or maintenance time.

## Exact score selection and tie resolution

Maintain one active index interval on each sorted arm. Form a weighted median pivot from the midpoint scores of the nonempty intervals, giving each midpoint its interval's cardinality as weight. Binary search each interval for the counts strictly below and weakly below the pivot. If the requested rank is in the pivot's tie block, return the pivot. Otherwise discard all scores on the opposite side, including the pivot and its ties, and adjust the rank when discarding from the low end. At least half the combined weight has midpoint scores weakly on the discarded side, and each such interval discards at least half its items. Thus each nonfinal round removes at least one quarter of the remaining items, so soft-O(number of arms) operations suffice. This uses only comparisons and also applies when many midpoint scores coincide.

For lexicographic tie breaking, use the original complete arms rather than the trimmed selection intervals. Count the scores strictly below the returned score on each arm by binary search and subtract their total from the requested rank. The equal-score items in each arm occupy a contiguous interval in original coordinates even if that arm was reversed. Visit arms in original index order and subtract the tie counts until the desired interval is reached; return the corresponding original index. Reversing a descending arm by itself would not preserve equal-index order.

The total number of arms is O(pq+H). Reporting both extrema, building the arms, selecting, and resolving ties prove the stated all-cell bound. No enumeration with a cost proportional to individual plateau lengths is needed after the static input preprocessing.

## Context and verification

[Frederickson–Johnson](https://www.sciencedirect.com/science/article/pii/0022000082900484) and [Kaplan–Kozma–Zamir–Zwick](https://arxiv.org/abs/1802.07041) give classical sorted-list selection algorithms. The proof above uses an elementary weighted midpoint argument instead. [Min-plus witness counting and parity](https://arxiv.org/html/2610.06783v1) concern witnesses of a minimum, not the order statistic of all addends. The ICALP 2026 [deterministic monotone min-plus algorithm](https://doi.org/10.4230/LIPIcs.ICALP.2026.119) returns minima and assumes bounded monotone integer entries in one factor, rather than sparse turns in the summed profiles. No priority claim is made.

- `node minplus-quantile-weighted-midpoint-replay.js` checks 3,280 signed profiles, 105,796 intervals, and 340,762 ranked keys. It implements weighted-midpoint selection and simulates the first-nonzero oracle by scanning. It does not implement the static all-pair reporter or benchmark query latency.
- `MinPlusQuantileCertificate.lean` checks only `positive_suffix_monotone` and `weighted_pivot_shrinks` under Lean 4.34.1 and mathlib `d13f23b723b8a846827a245b89c10fc7d3f11612`. The full algorithm and complexity are paper proofs.
