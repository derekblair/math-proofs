# Independent review of interval-sensitive deterministic real 3SUM

**Result:** conditional on the cited preprint results, I find the revised resource bound and Majdoddin substitution valid, including for degenerate real inputs by explicit tags. This is an independent paper audit of changed steps, not a kernel-checked implementation, line-by-line re-verification of the full rectangular product, or public priority/record certification.

## Reduction and resource ledger

[Chan–Itakura–Ma–Yu arXiv:2610.42012v1](https://arxiv.org/html/2610.42012v1), §5:
1. Lemma 5.8 expands squared rank into two witness pairs after a threshold comparison. Tuple keys are six positional coordinates (k,\ell,k',\ell',k'',\ell''), and three dyadic rank intervals. The middle-set paragraph's final (\ell') is a transcription typo; use (I\times[d]^5) as in the displayed sum. A strict rank inequality uniquely chooses the first split where the two ordinal ranks land in opposite halves; use right rank (+1) to represent `<=`. Ranking the union of differences together (including a consistent convention on ties) is valid. No input-real multiplication, floor, or conversion is introduced.
2. Regard the two side incidence arrays as fixed for each row interval, independently of the query-pair relation. Each of the n endpoints on either side examines |I| d^5 coordinate tuples and O(log³ n) combinations of interval ancestors. Enumerate only these actual incidences, sort word-sized tuple records deterministically to assign middle IDs and form adjacency lists. Across eligible dyadic intervals, sum |I|≤d(1+log d). For lower rank powers omit unused witness pairs; don't count dummy copies (which would multiply the moment).
3. For light middle vertex w enumerate L(w)×R(w), and add 1 to a deterministic sorted query dictionary if its endpoint pair is requested. Work at most degree(w)^2≤Δ·degree(w). Membership and updates cost logarithms, absorbed. Query records need O(n²/d) aggregate word operations up to logs (deduplicate repeated endpoint pairs *within each interval and moment/relation type*, and fan out the answer). A requested pair never influences the light/heavy distinction. The source's total O(n²/d) requests, not O(n²/d) per interval, is exactly Problem 5.6's promise. In light processing no full n×n table is initialized.
4. With Δ = Θ(n/d^(6+δ)), light processing is Õ(n²/d^δ). Width of interval I's heavy incidence matrices ≤ total incidence/Δ = Õ(d^(11+δ)|I|) ≤ Õ(d^(12+δ)). Pad to a common width D=Õ(d^p), p=12+δ. Only with strict pα<R can thisÕ padding be accepted. Take d a power of two within a factor of two of n^α; width threshold can also be rounded by constant factors using word logarithms and exact rational exponents. Each matrix is genuinely dense on input to the backend even though the graph is sparse: O(nD) zero-fill per interval, total Õ(n d^(p+δ)), exponent about 1.0732 and strictly below target. Pad n by lower-order factors to whole blocks, using tagged/marked sentinels if needed. Query matrices contain 0/1 entries. All list IDs, rank powers, output moments, count products, and threshold arithmetic fit a constant number of O(log n)-bit words.
5. A separate deterministic selected-entry index per occupied interval (and per constant many moment/inequality types) costs Õ(n²d^(δ−pγ)); aggregate queries cost Õ(n²d^(pq−1)). No division of W or additional query factor d^δ applies. Across different calls from Lemmas 5.3/5.5/5.7 at most polylogarithmically many repetitions are charged. Binary search on B in each row of the final strip (Lemma 5.5, proof after dyadic split) costs Õ(n²/d^δ). The source has a minor presentation mismatch at the final threshold crossing: use counting down to intervals of length at least half d^(1−δ), i.e. one extra level, then finish with a strip O(d^(1−δ)). This preserves eligible interval count and powers. The chosen branch is justified by nonempty weighted average, avoiding the repeated (I^{-}) typo in the printed right-child statement.

## Degenerate reals and candidate selection

The source explicitly assumes no equal pair sums at §5 around Problem 5.1. Fix it by attaching additive lexicographic integer tags: given sorted inputs (or first sort by real and break ties by ID), use tag i+1 for element i of A, and tag (j+1)S for element j of B, with S larger than every A tag. Distinct pairs obtain different tags. Their original real sums remain the first coordinate; differences rank by lexicographic comparison, so Fredman rearrangements still hold and a real comparison remains constant size. For a target c search lexicographic successor of (c,0). Since all pair tags are positive, every original equality lies strictly after (c,0), before every original value greater than c. Return YES exactly if the first coordinate of the lexicographic successor equals c. Do not test lex equality. Strict predecessor and ≥ successor are precisely the definitions in §5 footnote 12; the terminal per-row binary search is Lemma 5.5. For blocks whose minimum already exceeds the lex target return this minimum directly; for blocks with no successor skip. If implementing candidate staircases via block overlaps only, exact matches at block minima can also be checked in O(n/d) per c using two pointers on the block-minimum lists. All other matching blocks straddle the lex target. The standard monotone staircase O(n/d) bound applies, since lexicographic block extrema of each list are strictly separated. The single-list distinct-index variant reduces to three disjoint lists with O(log² n) overhead by enumerating two bit positions in identifiers and assigning the three positions three distinct 2-bit colors.

## Majdoddin and competitors

The actual data structure is Corollary 7.3 of [Majdoddin arXiv:2610.17420v1](https://arxiv.org/html/2610.17420v1), not Theorem 7.1 (the latter is the slot/box identity underlying the proof). Corollary 7.3 explicitly allows deterministic preprocessing of arbitrary integer entries bounded by N^O(1), width 2≤D≤N^ε for ε<R'_c(γ), and individual exact deterministic queries; the arrays here meet that statement even after padding, with strict slack. Its proof uses width rounding to powers of 4 and O(log N)-bit words. The gamma/query/radius equations used by root match exactly; source denominator R' is `c ln 5 − (c/2) H(1/c) − (c−1) ln 2 + γ ln 2`, query entropy denominator ln 2. The extra log³ preprocessing cost is absorbed, not omitted from the exponent accounting. This audit does not certify every proof step of Majdoddin.

Searches of the current primary literature found the stated comparison-based deterministic real 3SUM benchmark O(n^1.9998) in Chan et al. Cor. 5.10, not a newer explicit deterministic arbitrary-real comparator. Majdoddin's listed O(n^1.99450+o(1)) is **integer**, and his §1 discussion explicitly says the prime hashing of Part II does not apply to arbitrary reals. Its composition with Alman–VW Theorem 35 improves an already faster Las Vegas result, not the deterministic comparison. Karingula–Lovett arXiv:2610.15663 explicitly targets polynomially bounded integers. Fischer–Polak–Schmidt arXiv:2610.10153 supplies randomized reduction stages, not an immediate deterministic comparator. The unmodified Chan et al. reduction with Majdoddin's newer backend already beats the literal O(n^1.9998), and that inherited quantitative comparison is the meaningful one (root's numerical old-method envelope approximately 1.999628164). I found no primary publication stating the interval-sensitive computation, but search is not a proof of novelty and the change is a modest exponent-accounting improvement. Avoid “speed record” unless priority and stronger same-model implementations are independently checked.
