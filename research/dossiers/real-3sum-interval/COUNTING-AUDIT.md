# Independent review: exact per-target real 3SUM counts

The claimed bound is a valid corollary of the weighted rank-moment algorithm, provided its predecessor/successor query guarantees hold as in Chan–Itakura–Ma–Yu [arXiv:2610.42012v1](https://arxiv.org/html/2610.42012v1), §5. It uses the same comparison/addition model and deterministic runtime, not a decision-to-count black-box reduction. I found no exact-model scope error. This is paper-level review, not a formal end-to-end implementation.

## Brackets, cuts, and complexity

Attach positive, unique additive pair tags less than T; exact real equality a+b=c lies strictly between (c,0) and (c,T) in lex order. Count strictly below each threshold. Any rectangle with max<q contributes its full size, counted via monotone block-max pointer and prefix counts of actual B-block sizes. Any rectangle with min≥q contributes zero. All others have min<q≤max, and each sorted block pair gives exactly min and max at its two opposite corners. If i<i' and j<j', then earlier max<later min (sorted tagged A/B blocks are strictly separated), so the two cannot both cross. Thus if two crossing rectangles had equal i-j, they would have both coordinates strictly increasing, contradiction. Each row's two cut indices are monotone, so rectangle discovery costs O(number blocks + crossing count), including unfinished final blocks and empty lists.

Problem 5.2 gives its initial min/max bracket exactly as min<q≤max with the input indices. The returned-bracket display has a p-prime-minus paired with q-prime-plus typography error, but Lemma 5.5's binary search explicitly returns the predecessor/successor pair and its mathematical witness is correct. If gap is exactly one, no recursion is needed; if larger it contains actual interior ranks. Midpoint pivot bounds force geometric progress, and Lemma 5.3 supplies O(log d) rounds. Allow one final additional dyadic level if the threshold is crossed; its lengths within a factor 2 preserve the complexity. A final zeroth-rank-moment weak query for the returned predecessor counts exactly all lex sums below q. A degenerate real sum's different tags are still separate positions; output count retains multiplicity. The two cuts yield O(n²/d) total cross-rectangle queries plus the inherited polylogarithmic reductions, and extra moment requests respect the weighted algorithm's stated budget.

For the three-list case repeat C positions or aggregate duplicate targets and multiply their counts; sums ≤n³. In the same-list variant a+b=c with fixed target position k and f the value frequencies, correct its raw count by subtracting count{ i : 2a_i=a_k }+2f(0) and adding 2·[a_k=0]. This is inclusion-exclusion among i=j, i=k, j=k; pairwise and triple intersections all coincide at i=j=k. The first term can be found for each k using sorted comparison against twice an entry (no real division required). Ordered versus unordered counting can be specified explicitly (for a fixed k, remaining i/j are distinct and interchanged by swapping, so divide by 2 if desired). For the symmetric zero-sum formulation summed over all targets, subtract 3∑_i f(−2a_i) and add 2f(0), then divide by six if wanting unordered distinct triples.

## Prior and novelty

- Chan et al. explicitly solve predecessor/successor and already expose rank moments. At their deterministic exponent the same per-target count follows immediately from two threshold cuts, even though §5 states decision. This is close conceptual overlap; avoid any assertion of first deterministic polynomial improvement for counting.
- Chan–VW–Xu [arXiv:2303.14572](https://arxiv.org/html/2303.14572), Theorem 8.10, explicitly treats #All-Nums-3SUM as a randomized reduction from All-Nums-3SUM by way of convolution. Its integer hashing provenance does not immediately make it a deterministic arbitrary-real theorem.
- Fischer–Jin–Xu [arXiv:2410.20764](https://arxiv.org/html/2410.20764) proves deterministic fine-grained counting/detection equivalence using modular integer operations, so does not directly certify a competing arbitrary-real deterministic bound or identical exponent. Alman–VW [arXiv:2610.06783v1](https://arxiv.org/html/2610.06783v1) explicitly mentions count consequences, but its §5.2 real reduction uses Las Vegas randomization.
- No newer primary source found explicitly stating a better arbitrary-real deterministic per-target exact count, but the search is not exhaustive. Report as a matching-exponent corollary, not a separate priority claim.

## Exact Triangle barrier

The predecessor form in Chan–VW–Xu [arXiv:2203.08356](https://arxiv.org/html/2203.08356) Problem 3.2/4.1 asks about A[i,k]+B[k,j], with *shared* k, rather than the independent k and l of 3SUM. In the rank expansion, each witness k' is shared too. Eliminating these shared labels by multiplying separately summed marginals would count off-diagonal indices. For example, d=2, A=(0,10), B=(11,0) and pivot index 1 (zero-based) give diagonal candidate sums 11,10 and no strictly smaller candidate. Independent cross sums incorrectly include 0. Keeping each shared equality label or an equivalent coupling is necessary for this contraction; this does not imply a lower bound for all algorithms.

Even with shared k labels retained, per-output pivot p_{ij} appears in both rank-difference lists. Replacing n×n output with distinct pivot-colored endpoints (i,p),(j,p), or preprocessing separately for p, introduces extra rows or a factor d. Summing over pivot color loses the rank needed for each (i,j); an ordinary single product output cannot select that varying pivot. No verified generic bypass from the weighted 3SUM contraction. Chan et al. already sketch a qualitative deterministic exact-triangle transfer using older reductions; do not present this barrier as excluding a deterministic subcubic algorithm.
