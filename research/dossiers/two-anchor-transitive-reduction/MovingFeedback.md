# Varying feedback certificates in fully dynamic transitive reduction

The dynamic result is for a simple digraph on a fixed vertex set with the stated batch-update model.

This strengthens the dynamic portion of `FixedFeedbackSweep.md`. Let (G_t) be an initially empty digraph on a fixed n-vertex set, updated by the same vertex-centered insertion batches and arbitrary deletion batches used in [Goranci–Karczmarz–Momeni–Parotsidis, Theorem 1.1](https://arxiv.org/html/2504.18161). Suppose a valid directed feedback vertex set (F_t) of size at most k is supplied for each final graph. Its membership may change arbitrarily at each update. We obtain the **same** deterministic (O((k+1)^2(n+m))) amortized time with explicit input reading, and (f(k)(n+m)) amortized time without supplied certificates by finding them per snapshot using [Lokshtanov–Ramanujan–Saurabh](https://arxiv.org/abs/1609.04347). These are feedback-parameter guarantees, not unrestricted bounds.

## Simulating one original update with an unchanged persistent DAG data structure

Represent (D_t=G_t-F_t) on the full fixed vertex set, with the feedback vertices isolated rather than deleting the IDs. The single maintained DAG reduction instance is never rebuilt. Let (F_0,F_1) be the previous and final feedback sets, (G_0,G_1) be the corresponding graphs, (D_0,D_1) their complements, (U=F_1-F_0) the entering anchors, and (W=F_0-F_1) the leaving anchors.

1. Delete (D_0-D_1) in one arbitrary deletion batch. Enumerate the exact set as (i) original deleted arcs that belonged to (D_0), and (ii) arcs still present in (G_1) that belonged to (D_0) and meet U. These sets are disjoint. In (ii) traverse the **final** incident lists of U, deduplicating arcs with both endpoints in U. Thus after a massive deletion the only scans of old, now-absent arcs are the explicitly supplied original deletion input. It is also sufficient to scan all of the final arc list once. After this batch the persistent graph is precisely (D_0∩D_1).
2. Enumerate (D_1-D_0) by one scan of the final arc list. An arc newly admitted to D that was already in (G_0) has at least one endpoint in W. Assign every newly admitted arc meeting W to a deterministic chosen leaving endpoint (e.g., the lesser numbered one), and issue at most |W| nonempty batches. Any remaining arc in (D_1-D_0) must be an originally new arc, hence is incident to the original update center; these form at most one more batch. No arc appears twice. It is harmless to merge two batches centered at the same vertex.
3. At every point after step 1, the persistent graph is a subgraph of the final DAG (D_1), so **no intermediate insertion batch ever introduces a cycle**. Vertex IDs and all DAG data structure state persist; the final state is exactly (D_1).

For enumeration, use dense membership already within the (O(n^2)) dynamic-space allowance, or original adjacency with per-arc update flags and arrays of the old/new anchor memberships. In the latter version, an old original arc's membership in (D_0) is just the complement-membership test of both endpoints, and an arc flagged newly inserted wasn't in (D_0). Deduplication does not require sorting a long old adjacency list. The scan overhead is (O(n+m_1+|batch size|)), where (m_i=|E(G_i)|), and each batch has the exact same allowed shape as the primary DAG theorem.

## Amortized analysis and answer

There are at most (k+2) DAG subupdates. All insert subupdates have graph size at most (m_1); if the deletion is charged at the maximum of the pre/post sizes it costs at most (m_0) in the source's amortized analysis. On any prefix of the simulated update sequence from empty, Σₜ mₜ₋₁ ≤ Σₜ mₜ, so the total maintenance charge for this portion is (O((k+1)sum_t m_t)). Reading the raw supplied batches is charged separately (with valid nonduplicated batches it is already bounded by the adjacent graph sizes). In particular this is an aggregate bound, not an individual update worst-case bound or impossibility claim after a large deletion.

Compute the full reduction from the current (F_t,D_t) using the SCC and condensation procedure in `FixedFeedbackSweep.md` and the current intra-SCC cut sweep; that work is (O((k+1)^2(n+m_t))) worst-case. The SCC decomposition is rebuilt only for output/composition, not for the persistent DAG data structure. Every true condensation edge representative is treated exactly as before; the proof depends only on current (F_t), not on its history. Overall dynamic space inherits (O(n^2)) from the one DAG structure. When the graph remains in the promised class DFVS(Gₜ) ≤ k, the cited linear-FPT finder gives a fresh witness with (O(k!4^k k^5(n+m_t))) extra time for k≥1. The graph can start empty with any legal (F_0); no dynamic DFVS data structure or initial nonempty construction is assumed. The supplied-certificate variant is a promise. If validating a witness, check IDs, size, and acyclicity of the final complement before changing the persistent DAG; this costs O(n+m) per snapshot.

## Controls

`moving.py` independently tracks exact (D), checks every intermediate simulated insertion is acyclic and correctly centered, verifies no duplicate insertion, checks exact final complements, then checks complete reachability and every output edge's necessity against brute-force searches. It includes changes on insertion and deletion, varied F membership, batch deletion cases and n up to 12. This tests the composition, not the cited DAG data structure's internal implementation or complexity.

Final verification: 27,195 updates, 18,732 changed certificates (9,065 with an original insertion and 9,667 without), with up to five centered insertion subbatches in one update. The simulation issued 46,215 deletions and 47,312 insertions to the persistent masked DAG. `MovingFeedback.lean` proves exact deletion set identity, the origin classification of every newly admitted arc, and inherited topological safety for every intermediate subgraph, with standard axioms and no holes. Focused follow-up search found the primary unrestricted dynamic paper but no exact varying-certificate counterpart; this is not a priority certification.
