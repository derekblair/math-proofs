# Mixed endpoint tags for fixed-terminal exact three-failure distance oracles

Model: simple directed graph on n vertices, arbitrary finite real edge weights, no negative directed cycles; fixed s,t and queries of at most three failed original edges. Unit real addition/subtraction/comparison, with ordinary word-index addressing on O(log n)-bit indices as in the adjacent batched dossier. Let alpha be any fixed available deterministic exact real APSP exponent in (2,3), e.g. 2.9929729 from [Essayag–Zabokritskiy, arXiv:2611.17215v3, Thm. 1.1](https://arxiv.org/html/2611.17215v3). Two consequences:

1. O(n^alpha log³(2+n)) preprocessing, O(n²) persistent storage and O(1) queries whenever every failed edge has an endpoint in {s,t} plus two more vertices. On an arbitrary graph this promise is checked in O(1), by choosing which endpoint of each of at most three failed edges to anchor. Unlike the prior first-tag-only scheme, this includes a three-arc directed path of failed edges a→b→c→d even with distinct tails and heads and unrelated s,t; choose b,c as extra anchors. Arbitrary triple fallback can use the stopped tree of the [stopped hierarchy](../STOPPED-ORACLE.md).
2. If the underlying support has vertex-cover number h, all arbitrary queries of up to three edge failures take O(1) after Õ(n(h+1)^(alpha−1) + (h+1)³) deterministic preprocessing and O(n+(h+1)³) persistent words/real cells. Here the logarithmic loss need only attach to the first term. For fixed h the elementary first-phase construction below gives O(n) instead. This is a vertex-cover-parameterized exact bound, not a new unrestricted 3FRP exponent or an explicit table of every possible input-edge triple.

## Interface and sparse tag banks

An X-shortcut is a nonempty walk u→v with u,v in X but no internal X vertex. Store for each ordered pair a bank of tuples (weight, original hops, first original edge, last original edge), each representing a genuine shortcut. The invariant is that the bank contains a lex (weight,hops) optimum for every set of forbidden **side-labeled** edge IDs of total size at most f=3, considering only first/last edges. Left e and right e are distinct namespaces even when they happen to name the same original edge. A direct arc has both tags equal to its edge ID. Lists need not encode all best tags; each addresses only one-side/two-side exclusion tests.

A bank of at most 2^(f+1)−1 tuples suffices: select the cheapest allowed tuple, recurse one branch forbidding its first label, the other forbidding its last label, and stop after depth f. Empty nodes return no candidate. For any forbidden labels B, if the selected tuple violates B choose a branch whose newly banned label belongs to B. At depth <=|B| there are no further new bans compatible with following B. The selected allowed tuple is then a minimum among all tuples avoiding B because its branch excluded only a subset of B. This proof works for ties, same original ID on both sides, repeated forbidden labels and empty banks. Merge a union of banks and recompress in the same way, since the optimum of a union is the minimum of its constituent optima.

## Batched elimination and exact masks

To eliminate Z=X\\Y, compose X-shortcuts along paths with interior vertices in Z. A direct parent segment u→v for u,v in Y must honor both endpoint exclusion sets; the first segment u→z only honors the left set, last segment z→v only the right set; other segments impose neither restriction. This proves the child bank invariant at the level of parent banks: take an optimal constrained original shortcut and split at X. Replacing each segment by the corresponding optimal represented tuple cannot worsen (weight,hops) and still realizes a legal constrained walk. Conversely every composed candidate expands into a real walk with no internal Y vertex and the advertised first/last labels. Thus the invariant concerns only constraints on two ends, not arbitrary interior edge failures. Interior failure exclusion is application-specific below.

In a parent of k vertices the total number of stored IDs is O_f(k²). Sort them and use local word codes. Enumerate patterns fixing at most f positions across the **disjoint union** of bits of the left and right codes, with arbitrary required bit values. There are O_f(log^f(2+k)) patterns. For each pattern build a split auxiliary graph with two copies of Y (source-only and sink-only) and one copy of Z. For u in source side to z in Z choose best parent option with matching left bits, zero out the right tag; for z in Z to sink v do the reverse. For direct source u to sink v require both patterns and keep both tags. In Z-internal pairs both tags zero and select best ordinary lex weight/hops. Run exact APSP on weights (weight,hops,left code,right code). The code coordinates occur only at first/last arcs and cannot contaminate each other; first and last on a direct arc are encoded in separate coordinates. Real zero-length diagonal entries used by the APSP implementation are only padding; distinct source/sink copies ensure no zero-edge shortcut reaches the recipient. Cycles only traverse Z and expand to closed original walks, so are nonnegative; any zero-weight cycle has positive hop sum.

For a desired optimal parent-composed candidate that avoids B, compare its own code on each side to each forbidden label on that side. Choose one differing bit per forbidden label, and set it to the candidate's bit. The resulting pattern keeps the desired candidate, forbids all labels in B on their respective sides, and requires at most |B| bit positions across the two sides. A forbidden label not present in the parent codebook can be ignored. Thus the minimum returned by that pattern is an exact constrained optimum. Collect finite reports across patterns; recompress each pair as above. Any other returned item is a feasible underlying shortcut with the advertised tags and cannot underestimate its optimum. Batch cost O_f(k^alpha log^f(2+k)), including local remap, matrix formation and output processing. The comparison/addition-only real tuple lift and coefficient recovery by binary search, not real-to-word casts, are exactly the method proved in the [full-depth derivation](../REPORT.md), and add at most O(k² log k) per mask inside alpha>2.

## Failed-edge queries and endpoint cover

Choose a set of anchors X including s,t and at least one endpoint of every failed edge. For a failure e=(u,v) with u in X, ban left e. Otherwise v in X; ban right e. Inside an X-shortcut, an occurrence of the former must be the first edge, since its tail belongs to X. An occurrence of the latter must be the last edge, since its head belongs to X. If both endpoints are in X, the occurrence must be both first and last because an intermediate X vertex is forbidden. Hence a single side-label per failed edge suffices, even for a direct failed arc between two anchors. Failure incident to s or t costs no additional anchor; a chosen endpoint that coincides with a terminal is not duplicated. Parse the at most three optional extra endpoint choices with O(1) work.

Filter banks by these bans, take each cheapest surviving pair and run dense shortest paths on X (constant size in leaf queries); its weight/hops equal the original answer by decomposing a canonical original path at X and expanding each shortcut of a returned walk. The resulting expanded walk may *a priori* revisit anchors or original vertices outside X; it still avoids all failed edges, and removal of cycles never increases weight, preserving valid endpoints. Choosing the original hops tiebreak implies an optimal expanded walk has no repeated vertex, since any zero-weight cycle would strictly decrease hops if removed. Equal s,t is the empty answer. Unreachable stays infinite; no nonexistent path is inserted by any batch.

## Preprocessing counts and vertex cover

Build the dyadic tree with **two optional vertex slots** relative to fixed roots {s,t}; count O(2^(2j)) states of size O(n/2^j) on level j. A leaf contains the optional anchors, using a repeated filler or fixed terminal when fewer than two anchors are needed. The total is O(n^alpha log³(2+n)) because alpha>2. For distance-only retain just leaf banks, O(n²) persistent space. Recursion scratch is larger and separate. Compare with reversing the first-only construction: that helps when heads repeat but not when three distinct first and three distinct last vertices are repartitioned across two anchors.

For the promised support cover, find its factor-two approximation in O(n+m) by scanning for a maximal undirected matching and collecting its endpoints, or use a supplied cover. Add s,t, so the new core X has H=O(h+1) vertices and the remainder is independent. Every shortcut in this initial state is a direct arc or exactly two original arcs through a single noncore vertex, no long outside-core walk. Tile the outside vertices into groups of at most H. A tile plus core is O(H) vertices; process it with the masked batch starting from original single-edge banks on that induced graph. Union and recompress the banks across all tiles, also including direct core arcs. Recompression fits the per-tile cost and can stream, preserving only O(H²) accumulated tuples. This first phase costs O(n H^(alpha−1) log³(2+H)+n+m), and can alternatively enumerate all O(n H²) two-hop candidates with constant-size streaming merge, which removes a logarithmic loss for fixed H. Tile construction uses local IDs of size O(H²), so no log n leakage into the batch rate beyond index words. Then run the three-slot dyadic tree on H core vertices with its prebuilt bank; arbitrary queries always admit three or fewer anchors from the cover. Total core time O(H³) by the geometric calculation for the batched scheme, and persistent leaf space O(H³). Membership/core-index arrays of n words suffice; for a promised-valid query set, the original adjacency need not be retained just to retrieve an original edge ID (ordered pair in a simple graph). Scratch/input storage is not included in the persistent count.

## Prior scope

[Harada–Terao v1, Lemma 14 and §4](https://arxiv.org/html/2611.29061v1) proves an O(n³ log n) fixed-terminal 3-edge-failure exact distance oracle and announces a cubic bound; its first-edge-tag guarantee anchors every failed tail. This is not a claim to improve their unrestricted endpoint. [Bilò et al., ITCS 2022 Theorem 15](https://arxiv.org/html/2112.03059) already observes vertex-cover fault-distance compression and gives poly(h,f) query for unweighted distances, retaining common-neighbor availability; their formulas explicitly add 1/2 per terminal hop. It is not an arbitrary-real weighted or constant-query guarantee, and not a novelty claim for using vertex covers at all. [Bilò et al., ICALP 2026](https://drops.dagstuhl.de/storage/00lipics/lipics-vol374-icalp2026/html/LIPIcs.ICALP.2026.35/LIPIcs.ICALP.2026.35.html) give deterministic replacement-path coverings, with the covering correctness criterion bounded by a hop limit L. Covering alone does not supply the mixed-anchor theorem or its preprocessing/query bounds, and the two-optional-anchor result here constrains failure locations rather than original replacement path hops. [Weimann–Yuster Thm. 1.1](https://www.cs.haifa.ac.il/~oren/Publications/replacement.pdf) is randomized, arbitrary-endpoint and arbitrary-real, with different parameter profile. No absolute optimum or priority claim is made.

### Why a simple partition portfolio does not give a global improvement

For complete directed input, take three disjoint failed arcs on six distinct vertices outside s,t. Under any partition with block size at most b, allowing one endpoint from each of these arcs to fit inside only two extra blocks requires a pair of endpoints from different failed arcs in the same block. For a uniformly random choice of the distinct endpoints, each of at most 12 cross-arc pairs is in the same block with probability at most (b−1)/(n−3). Thus any fixed portfolio covering every such query with two b-block slots needs Ω(n/b) partitions (for b>1; b=1 cannot cover such a query at all). This is only a lower bound on that representation, not on oracle complexity. Paying a separate n^alpha-dominated two-slot preprocessing bound per partition loses the target stopped-tree improvement instead of amplifying it. A general gain needs shared preprocessing across partitions or a different aggregate.

Exact controls: 13,830 ordered-pair mixed exclusion entries (339 choices with the same original ID forbidden in both namespaces), 2,137 actual failed-edge queries (523 using a head-side ban; 1,061 with a failed arc entirely in the anchor set; 1,299 involving a terminal; 1,291 unreachable), and 2,840 tiled-versus-unsplit exact matching entries. The independent second-seed replay passed 18,510 constrained pairs, 2,511 failure queries and 3,408 tiled-bank comparisons in addition to the listed controls.
